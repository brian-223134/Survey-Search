# BM25 는 facet 이 켜지면 하는 일이 없습니다

**한 줄**: facet 없이는 R@1500 을 +3.1%p 올리는데, facet 을 켜면 **−0.6%p**(0과 구분
안 됨)입니다. 대신 검색 시간을 **5배**로 만듭니다.

**결론**: 권장 설정에 `lexical=False` 를 넣습니다. **BM25 를 빼라는 게 아니라
facet 과 겹쳐 쓰지 말라**는 것입니다.

## 왜 물었나

170토픽 표는 설정이 **누적**이라 `+facets` 행에도 BM25 가 켜져 있습니다. 그래서
아래 둘을 구분할 수 없었습니다:

- BM25 가 facet 위에서도 꼬리 recall 을 더해 주는가
- 아니면 **facet fan-out 이 이미 BM25 가 주던 것을 덮어서** 이제는 nDCG 손해만 남는가

facet 이 토픽을 하위 주제 12~16개로 쪼개고 각각 **표면형이 다른 쿼리**를 던지는 이상,
어휘 검색이 메우던 구멍을 이미 메우고 있을 수 있습니다.

## 결과 (같은 170토픽, 같은 실행)

| 설정 | R@50 | R@100 | R@500 | R@1500 | nDCG |
|---|---|---|---|---|---|
| + facets (BM25 **켬**) | 19.0% | 25.5% | 43.9% | 56.9% | 0.294 |
| + facets (BM25 **끔**) | 18.6% | 25.4% | **44.4%** | **57.5%** | **0.299** |

**격차가 0.5%p 수준이라 평균만 보고 결론 내면 안 됩니다.** 토픽별로 짝지어 봤습니다:

| | 평균차 (켬 − 끔) | BM25 승/패 | 판정 |
|---|---|---|---|
| R@50 | +0.40%p ± 0.29 (SE) | 60 / 48 | 판정 불가 |
| R@100 | +0.10%p ± 0.27 | 52 / 56 | 판정 불가 |
| R@500 | −0.51%p ± 0.35 | 57 / 71 | 판정 불가 |
| R@1500 | −0.57%p ± 0.32 | 54 / 74 | 판정 불가 |
| nDCG | −0.0054 ± 0.0062 | 81 / 89 | 판정 불가 |

**다섯 지표 모두 `|평균차| < 2×SE`** 입니다. 방향조차 단정할 수 없습니다.
즉 facet 이 켜진 상태에서 BM25 는 **측정 가능한 차이를 만들지 않습니다.**

## 대조가 결론입니다

"차이가 없다"는 그 자체로는 약한 결과입니다. 강한 건 **대조**입니다:

| BM25 를 켜서 얻는 R@1500 | |
|---|---|
| facet **없이** (dense only → +bm25) | **+3.1%p** |
| facet **있이** (+facets −bm25 → +facets) | **−0.6%p** (0과 구분 안 됨) |

**BM25 가 주던 +3.1%p 를 facet fan-out 이 전부 흡수했습니다.**

토픽을 하위 주제로 쪼개 표면형이 다른 쿼리를 던지면 — `"RAG"` / `"retrieval-augmented
generation"` / `"retrieval augmented LM"` — 어휘 검색이 메우던 구멍이 이미 메워집니다.
BM25 는 그 위에 얹혀 nDCG 만 조금 깎고 있었습니다.

## 그래서 속도가 판단 기준이 됩니다

품질이 같다면 싼 쪽이 이깁니다 (GPU 단독, n_papers=1500, 컷오프 없음):

| | 중앙값 (n=5) |
|---|---|
| facets + freshness (BM25 켬) | **13.9초** |
| facets + freshness (BM25 끔) | **2.6초** |

**5배**입니다. facet 쿼리 12~16개마다 DuckDB FTS 질의가 하나씩 붙는데, 그게 아무것도
안 하고 있었습니다.

## 누적 표만 봤으면 못 봤을 종류입니다

170토픽 표에서 `+facets` 행이 최고 성능이니, **그 안의 BM25 도 기여하는 줄 알았을
것입니다.** 실제로 이 프로젝트는 그렇게 믿고 BM25 를 권장 설정에 넣고 있었습니다.

단계를 하나씩 빼 보는 실험을 따로 돌려야 드러납니다. **단계별 분리 측정이 이 프로젝트의
존재 이유인 이유**가 여기 있습니다.

## 남은 질문

facet 이 BM25 를 덮는다면, **BM25 가 여전히 유일하게 잘하는 것**이 있는지는 아직
안 봤습니다. 예를 들어 facet LLM 이 모르는 컷오프 이후 신조어 — 그건 원래 BM25 와
스노우볼링이 메우기로 한 구멍입니다. 정답 집합이 2019~2023년 서베이라 이 실험으로는
검증되지 않습니다.

## 재현

```bash
python scripts/eval_surge_full.py          # 5설정 한 표 (약 35분, $0)
python scripts/eval_bm25_in_facets.py      # -bm25 설정만 따로 (약 31분)
```

두 번째 스크립트는 짝지은 비교(평균차 ± SE, 승/패)까지 찍습니다.
체크포인트가 있으면 검색 0회로 표만 다시 냅니다.
