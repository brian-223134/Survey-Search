# 1. 왜 만들었나 — 손대지 않은 첫 칸

## 서베이 생성 에이전트는 전부 같은 구조입니다

```
토픽 → [검색] → 논문 집합 → [개요 생성] → [섹션 작성] → 서베이
         ↑
      여기가 거의 비어 있습니다
```

AutoSurvey · SurveyForge · SurveyX 모두 개요 생성과 작성 단계에는 공을 들였습니다.
그런데 **첫 단계인 검색을 열어 보면** 이렇습니다.

| | AutoSurvey | SurveyForge |
|---|---|---|
| 쿼리 | 토픽 문자열 **1개** → top-1200 | 멀티쿼리 union + 2단계(1500편 서브셋) |
| 융합 | 없음 | union — **순위 정보를 버림** |
| 어휘 검색 | 없음 | `NotImplementedError` 스텁 |
| 재랭킹 | 없음 | 2년 시간창별 **인용수 정렬** |
| 인용 그래프 | 없음 | 없음 |

> 출처: 두 레포의 검색 경로를 직접 읽고 정리. 두 레포는 **읽기 전용**으로 두었습니다 —
> 고치면 "검색만 바꿨을 때의 효과"를 통제 측정할 수 없습니다.

여기서 문제가 둘 생깁니다.

## 문제 ① 데이터 신선도

배포본 DB 의 컷오프가 **AutoSurvey 2024-04 / SurveyForge 2024-09** 였습니다.
2026년에 "최신 동향 서베이"를 쓰라고 시키면 2024년까지의 논문만 봅니다.

이건 이미 해결했습니다 — 두 DB 를 **2026-08 스냅샷으로 최신화**하는 작업이
survey-search 이전에 끝나 있습니다.

## 문제 ② 랭킹이 최신 논문에 구조적으로 불리함

**그리고 이건 DB 를 최신화해도 해결되지 않습니다.** 이게 이 프로젝트의 출발점입니다.

- **SurveyForge** — `sort_by_citation_period` 가 시간창 안에서 **인용수로 정렬**합니다.
  최근 6~12개월 논문은 인용수가 구조적으로 0에 가까워, 검색에 걸려도 **랭킹에서 다시
  탈락**합니다
- **AutoSurvey** — 재랭킹이 없는 대신 토픽 임베딩의 최근접 이웃이 전부입니다.
  새로 등장한 하위 분야는 **용어 자체가 새로워서** dense 이웃에 애초에 안 잡힙니다

두 실패 모드가 다릅니다. 하나는 **랭킹**이 떨어뜨리고, 하나는 **후보에 못 들어옵니다.**

## 전제는 데이터로 확인했습니다

추측이 아니라 코퍼스를 세어 봤습니다.

| | |
|---|---|
| 코퍼스 전체 | **908,819편** (arXiv, 2026-08-04 스냅샷) |
| 2025~2026년 논문 | **277,804편 (30.6%)** |
| 그 구간의 인용수 중앙값 | **6** |

**인용수로 정렬한다는 것은 코퍼스의 3할을 구조적으로 뒤로 보낸다는 뜻입니다.**
"최신 동향"이 목적인 서베이에서 이건 치명적입니다.

> 발표 포인트: 이 표 하나가 프로젝트 전체의 정당화입니다. "최신 논문이 안 나온다"를
> 인상이 아니라 **분포로** 보여 줄 수 있습니다.

## 그래서 무엇을 만들었나

검색을 **끄고 켤 수 있는 단계로** 쌓았습니다. 이유는 두 가지입니다.

1. **각 단계의 기여를 분리 측정**할 수 있어야 "무엇이 실제로 효과가 있는가"에 답합니다.
   "검색을 바꿨더니 좋아졌다"는 논문이 못 되고, "어느 단계가 얼마나 기여했다"는 됩니다
2. 여러 서베이 에이전트가 **공유**해야 하므로 특정 호스트에 얽히면 안 됩니다
