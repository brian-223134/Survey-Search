# 3. 기존 것과 무엇이 다른가

교수님이 가장 관심 있어 하실 부분입니다. **네 개의 기술 축 + 하나의 방법론 축**으로
정리했습니다. 마지막 것이 실제로는 가장 방어하기 쉬운 차별성입니다.

## 한 장 대조표

| | AutoSurvey | SurveyForge | **survey-search** |
|---|---|---|---|
| 쿼리 | 토픽 1개 | 멀티쿼리 union | **LLM facet 분해 8~16개 × 1~3 표면형** |
| 융합 | — | union (순위 버림) | **2단 RRF** (facet 내부 → facet 간) |
| 어휘 검색 | 없음 | `NotImplementedError` | **DuckDB BM25** (측정 후 조건부로 끔) |
| 랭킹 | 유사도만 | 시간창별 **인용수 정렬** | **연령 정규화 인용률 백분위 × recency** |
| 인용 그래프 | 없음 | 없음 | **전방·후방 스노우볼링** (S2 API) |
| 컷오프 이후 | 불가 | 불가 | **온라인 백엔드로 보강** |
| 계측 | 없음 | 없음 | **단계별 `stats` — 버린 건수까지** |
| 평가 | — | — | **정답 170토픽 단계별 ablation** |

---

## 축 ① 쿼리 — 점 하나에서 부채꼴로

**기존**: 토픽 문자열 하나를 임베딩해 최근접 이웃을 봅니다. 즉 **임베딩 공간의 점
하나 주변**만 봅니다.

**여기**: LLM 이 토픽을 하위 주제 8~16개로 쪼개고, 각 facet 마다 **표면형이 다른**
쿼리를 1~3개 받습니다.

```
"RAG"  /  "retrieval-augmented generation"  /  "retrieval augmented LM"
```

방법론·모델·데이터셋 이름을 넣도록 요구합니다 — Self-RAG, IRCoT, DPR, FEVER, CodeT5.
**dense 임베딩이 구조적으로 못 잡는 것이 정확히 이 토큰들입니다.**

> **측정 결과 이 단계 하나가 상승분의 대부분입니다** — R@1500 +15.2%p, nDCG +0.077.
> 나머지 단계를 다 합친 것보다 큽니다 ([05](05-results.md)).

## 축 ② 융합 — union 이 아니라 RRF

**기존**: SurveyForge 는 멀티쿼리를 던지고 결과를 **union** 합니다.
합집합은 **"몇 번째로 나왔는가"를 버립니다.** 세 쿼리가 모두 1위로 뽑은 논문과
한 쿼리가 900위로 뽑은 논문이 같아집니다.

**여기**: 순위 기반 RRF 로 합칩니다. 여러 쿼리의 **합의**가 점수가 됩니다.

그리고 이 인덱스에서는 RRF 가 **선택이 아니라 필수 조건**입니다 —
쿼리 벡터가 비정규화(norm ≈ 24)라 **쿼리 간 점수 비교가 애초에 불가능**합니다.
점수로 합치는 방법은 여기서 성립하지 않습니다.

> 발표 포인트: "RRF 를 썼습니다"가 아니라 **"이 인덱스에서는 점수 융합이 불가능해서
> 순위 융합밖에 답이 없었습니다"** 라고 말하면 설계 근거가 됩니다.

## 축 ③ 랭킹 — 절대 인용수가 아니라 또래 대비 속도

**이 프로젝트의 원래 가설이 여기 있습니다.**

**기존 (SurveyForge)**:
```
2년 시간창으로 자르고 → 창 안에서 citation_count 내림차순
```
최근 6~12개월 논문은 인용수가 구조적으로 0에 가깝습니다.
**검색에 걸려도 랭킹에서 다시 탈락합니다.**

**여기**:
```
citation_rate = citation_count / max(months_since_pub, 3)
→ 6개월 코호트 안에서의 백분위
final = rrf × (1 + α·percentile) × (1 + β·recency)
```

2026년 논문의 인용수 3과 2019년 논문의 인용수 3은 **전혀 다른 의미**입니다.
"얼마나 많이 인용됐나"가 아니라 **"또래 대비 얼마나 빨리 인용되고 있나"** 를 봅니다.

> 측정: freshness 는 **recall 을 안 건드리고 nDCG 만 +0.040 올립니다.**
> 같은 논문을 더 앞에 놓는다는 뜻이고, 이게 정확히 의도한 동작입니다.

## 축 ④ 신호 — dense 하나에서 넷으로

| 신호 | 무엇을 잡나 | 기존 |
|---|---|---|
| dense | 말이 비슷한 논문 | ✅ 유일한 신호 |
| BM25 | **단어가 겹치는** 논문 — 새 방법론명·약어 | ❌ (스텁) |
| 인용 그래프 | **저자가 직접 선언한** 관계 | ❌ |
| 온라인 | 스냅샷 컷오프 **이후** 논문 | ❌ |

실측: BM25 는 dense 가 전혀 못 찾은 논문 **234편**을 데려왔습니다.
전방 인용(`cited_by`)은 **컷오프 이후 논문이 나오는 유일한 경로**입니다.

## 축 ⑤ (진짜 차별성) 방법론 — 무엇이 효과 있는지 말할 수 있는 구조

앞의 넷은 "더 좋은 검색"이고, 사실 각각은 다른 데서도 볼 수 있는 기법입니다.
**진짜 차별성은 이겁니다:**

> 기존 연구는 **"검색을 바꿨더니 서베이가 좋아졌다"** 까지만 말할 수 있습니다.
> 여기는 **"어느 단계가 얼마나 기여했고, 어느 단계는 오히려 손해였다"** 를 말합니다.

이걸 가능하게 하는 것이 셋입니다.

**① 설정 스위치 = 실험 축**
`SearchConfig` 의 불리언 하나하나가 단계 하나에 대응합니다. 같은 코드로 ablation 을
돌리므로 "실험용 코드"와 "제품 코드"가 갈라지지 않습니다.

**② 정답 집합이 있습니다**
SurGE 의 GT 서베이 205편 × `all_cites` — **서베이가 실제로 인용한 논문 집합이
곧 그 토픽의 정답**입니다. 170토픽 전체로 쟀습니다.

**③ 계측이 강제됩니다**
모든 단계가 자기가 버린 건수를 `stats` 에 신고합니다. 껐을 때(`skipped=True`)와
고장 났을 때가 **구분됩니다.** facet 이 실패해서 규칙 기반으로 내려가도 그 사실이
남습니다 — 안 그러면 **facet 을 켠 실험과 끈 실험이 구분되지 않습니다.**

### 그래서 나온 결과가 이겁니다

**"당연히 좋을 것" 세 개가 정답 기준으로 기준선 미달이었습니다** —
다양성(MMR), cross-encoder 재랭킹, 그리고 facet 이 켜진 상태의 BM25.
단계별 분리 측정이 아니었으면 **셋 다 켠 채로 좋다고 보고했을 것입니다.**

## 부수적이지만 물어볼 만한 차별성

- **드롭인 어댑터** — 호스트 코드 한 줄만 바꿔 끼웁니다. 그래야 "검색만 바꿨을 때의
  효과"를 통제 측정할 수 있습니다. 베이스라인 레포는 **읽기 전용**으로 둡니다
- **결정적 파이프라인** — LLM 은 facet 분해에만 쓰고 캐시합니다. 온라인 호출도 전부
  캐시합니다. 같은 입력이면 같은 결과 (170토픽 재실행으로 확인: R@1500 소수 4자리까지
  동일, nDCG 최대 편차 1.1e-5)
- **재임베딩 0** — 기존 gte 인덱스를 그대로 재사용합니다. GPU 시간을 안 씁니다
