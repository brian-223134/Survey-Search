# 주 결과 — 각 단계가 얼마나 기여하는가 (토픽 170개 = 전체)

**한 줄**: facet 분해가 압도적입니다. R@1500 **38.7% → 57.5%**, nDCG **0.200 → 0.299**.
나머지 단계는 작거나(freshness) 없거나(BM25) 해롭습니다(다양성·재랭킹).

**권장 설정**: `SearchConfig(n_papers=1500, facets=True, freshness=True, lexical=False)`

## 조건

| | |
|---|---|
| 토픽 | **170개** — SurGE 정답 서베이 전체 |
| 평균 정답 | 72편 |
| `n_papers` | 1500 |
| 날짜 컷오프 | 서베이별 `date_max=<게시일>` ([왜 필수인가](evaluation-setup.md)) |
| 실행 | 2026-08-13 05:45~06:19 (34분), 검색 850회, LLM 호출 0회 |

**설정은 누적입니다** — `+bm25` 행은 dense + BM25, `+facets` 행은 거기에 facet 과
freshness 까지 켠 것입니다.

## 결과

| 설정 | R@50 | R@100 | R@500 | R@1500 | nDCG |
|---|---|---|---|---|---|
| dense only (= 기존 방식) | 15.4% | 21.5% | 36.3% | 38.7% | 0.200 |
| + BM25 | 13.4% | 18.9% | 35.4% | 41.7% | 0.177 |
| + freshness | 14.0% | 20.1% | 36.4% | 41.7% | 0.217 |
| + facets | **19.0%** | **25.5%** | 43.9% | 56.9% | 0.294 |
| **+ facets, BM25 끔 (권장)** | 18.6% | 25.4% | **44.4%** | **57.5%** | **0.299** |

단계별 증분:

| 단계 | R@50 | R@1500 | nDCG |
|---|---|---|---|
| → + BM25 | −2.0%p | **+3.1%p** | **−0.023** |
| → + freshness | +0.6%p | ±0.0%p | **+0.040** |
| → + facets | **+5.0%p** | **+15.2%p** | **+0.077** |
| → BM25 끄기 | −0.4%p | +0.6%p | +0.005 |

## ① facet 분해가 압도적입니다

R@1500 **41.7% → 56.9%** (+15.2%p), nDCG **0.217 → 0.294** (+0.077).
다른 모든 단계를 합친 것보다 큽니다.

가설이 확인됐습니다 — LLM 이 토픽을 하위 주제로 쪼개면서 내놓는 **방법론·데이터셋
이름**(Self-RAG · IRCoT · DPR · FEVER · CodeT5 같은 것들)이 dense 임베딩의 사각지대를
정확히 메웁니다. 토픽 문자열 하나는 임베딩 공간의 점 하나라 그 근처만 보는데,
새로 생긴 하위 분야는 **용어 자체가 새로워서** 그 근처에 없습니다.

## ② BM25 는 facet 이 없을 때만 일합니다

| BM25 를 켜서 얻는 R@1500 | |
|---|---|
| facet **없이** (dense only 대비) | **+3.1%p** |
| facet **있이** | **−0.6%p** — 0과 구분 안 됨 |

facet 이 켜지면 하는 일이 없어집니다. 자세한 것은 [bm25-in-facets.md](bm25-in-facets.md).

**BM25 자체가 나쁜 게 아닙니다** — facet 을 안 쓸 거면 켜 두세요. 다만 facet 과는
같은 구멍을 메웁니다.

## ③ freshness 는 recall 을 안 건드리고 순서만 개선합니다

R@1500 이 41.7% 로 **동일**한데 nDCG 가 0.177 → 0.217 (**+0.040**).
**같은 논문을 더 앞에 놓는다**는 뜻이고, 이게 이 프로젝트의 원래 가설이었습니다.

BM25 가 깎아먹은 nDCG(−0.023)를 되돌리고도 남습니다.

## ④ 다양성과 재랭킹은 켜면 손해입니다

| 설정 | R@1500 | nDCG |
|---|---|---|
| facets (기준선, 16토픽) | **59.1%** | **0.288** |
| + MMR λ=0.3 | 38.3% | 0.182 |
| + rerank FACET | 51.3% | 0.172 |

→ [diversity-mmr.md](diversity-mmr.md) · [reranking.md](reranking.md)

**공통 원인은 둘 다 facet 이 만든 다중 쿼리 합의(RRF) 신호를 파괴한다는 것입니다.**
이 파이프라인에서 그 신호가 가장 값지다는 뜻이기도 합니다.

> 위 두 행은 **토픽 16개** 기준입니다(기준선 59.1% / 0.288). 170토픽 표와
> 직접 비교하지 마세요.

## 표본을 16 → 170 으로 늘려 달라진 것

| | 16토픽 | 170토픽 |
|---|---|---|
| facet 의 R@1500 | 59.1% | 56.9% |
| MMR·재랭킹 결론 | 손해 | (16토픽만 측정) |
| **BM25 의 nDCG** | 0.189 → 0.189 (**무해**) | 0.200 → 0.177 (**−0.023**) |

**결론이 바뀐 것은 BM25 하나입니다.** 16토픽에서는 "머리를 깎고 꼬리를 늘리되 순서는
안 건드린다"였는데, 170토픽에서는 **순서도 깎습니다.**

나머지는 최대 편차가 facet 의 R@1500 −2.2%p 로 안정적입니다. **16토픽 표본이 운이
좋았던 게 아니었습니다.**

> **교훈**: 격차가 작은 항목을 작은 표본으로 결론 내지 마세요. 격차가 큰 항목
> (facet +0.077, MMR −0.106)은 16토픽에서도 안전했습니다.
