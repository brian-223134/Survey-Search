# 평가 설계 — 정답을 어디서 얻고 어떻게 채점하는가

**한 줄**: 실제 서베이 논문이 인용한 논문 목록을 정답으로 씁니다. 서베이 170편,
평균 정답 72편.

## 정답 집합

문서 초안 단계에서는 "SurGE 벤치마크 구현이 미공개라 정량 평가 보류"로 적어 두었는데,
**직접 확인하니 그 전제가 틀렸습니다.**

[SurGE](https://github.com/oneal2000/SurGE) 의 `data/surveys.json` 에 GT 서베이 205편이
있고, 각각 `survey_title`(토픽)과 `all_cites`(그 서베이가 실제로 인용한 논문 목록)를
가집니다. **서베이가 인용한 논문 집합이 곧 그 토픽의 정답입니다.**
README 가 언급하는 `data/queries.json` 은 배포본에 없지만 없어도 됩니다.

우리 코퍼스와의 연결은 **정규화 제목**으로 합니다 — SurGE 코퍼스에는 arXiv id 가
없습니다.

```
인용 13,485편 중 12,324편(91.4%) 연결   |   서베이별 매칭률 중앙값 92.1%
205편 중 170편 사용
  └ 제외: all_cites 없음 9편, 정답 10편 미만 26편
```

## 날짜 컷오프가 필수인 이유

GT 서베이는 2019~2023년입니다. **2020년 서베이는 2021년 논문을 인용할 수 없습니다.**

컷오프 없이 평가하면 우리 파이프라인이 최신 논문을 밀어주는 만큼 **자동으로 깎입니다.**
가설을 검증하는 게 아니라 구조적으로 지는 실험이 됩니다. 그래서 서베이마다
`date_max=<게시일>` 을 겁니다.

컷오프를 걸어도 freshness 가설은 그대로 시험됩니다 — 서베이는 **당대 기준** 최신 논문을
많이 인용하므로, 인용수 정렬보다 연령 정규화 랭킹이 더 잘 맞아야 합니다.

> **컷오프는 `date` 가 아니라 `submitted_date` 기준입니다.** 원본 DB 의 `date` 는 v1
> 게시일이 아니라 **최신 버전 갱신일**이라, 2019년 논문이 2024년에 개정됐다는 이유로
> 2020년 시점 검색에서 탈락합니다. 실측 탈락률 7.07% → 6.75%.

## 도달 불가능한 몫

**recall 상한은 100% 가 아니라 약 93% 입니다.** 서베이가 개정되면서 나중 논문을 인용한
경우가 6.75% 있어, 컷오프를 정확히 걸면 원리적으로 찾을 수 없습니다.

이 6.75% 를 "우리 잘못"으로 세면 모든 설정이 똑같이 손해를 보므로 **비교에는 지장이
없습니다.** 다만 절대 수치를 읽을 때는 감안해야 합니다.

## 지표

| | 무엇 |
|---|---|
| **R@k** | 정답 중 상위 k 안에 든 비율. 서베이는 수백~수천 편을 모으므로 **R@1500 이 주 지표** |
| **nDCG** | 순위 품질. 같은 논문을 더 앞에 놓으면 오릅니다 |

**id 는 base_id 로 맞춥니다.** 검색은 `2401.12345v2` 를 돌려주는데 정답은 버전 없는
id 입니다. 버전을 안 떼면 전부 불일치가 나서 recall 이 0 이 됩니다.

## 돌리는 법

```bash
python -m survey_search.eval.surge --build-gold      # 정답 캐시 (1회, 약 3분)
python scripts/run_surge_eval.py --limit 16          # 빠른 확인
python scripts/eval_surge_full.py                    # 170토픽 전체
```

**1시간 넘는 평가는 체크포인트를 켜세요.**

```bash
python -m survey_search.eval.surge --checkpoint data/eval.ckpt.jsonl
```

(설정,토픽) 쌍 하나가 끝날 때마다 JSONL 한 줄을 `fsync` 로 내려씁니다. 같은 명령으로
다시 돌리면 그 지점부터 이어갑니다 — `kill -9` 로 죽여도 한 줄도 안 잃습니다.
첫 줄에 **실험 조건 지문**(설정·`n_papers`·컷오프)이 박혀 있어서, 조건이 다른 결과를
이어붙이려 하면 **거부합니다.** 설정이 섞인 표는 조용히 거짓말을 하기 때문입니다.

`scripts/watch_surge_eval.sh` 가 그 위에서 죽음(60초)·정지(25분)를 판정해 재시작합니다.
체크포인트가 없으면 재시작이 곧 처음부터라, 이 감시자는 체크포인트가 있어야 성립합니다.

> **체크포인트는 30토픽분을 날리고 나서 붙였습니다.** 1차 실행이 결과를 메모리에만
> 들고 있었고, LLM 호출 하나가 19분을 잡아먹어 죽여야 했습니다.

## 표본 크기에 대해

**16토픽으로 시작해 170토픽으로 늘렸습니다.** 그 결과 판단이 하나 바뀌었습니다 —
BM25 의 nDCG 효과가 16토픽에서는 무해(0.189 → 0.189)해 보였는데 170토픽에서는
**−0.023 으로 분명한 손해**였습니다.

교훈: **격차가 작은 항목을 작은 표본으로 결론 내지 마세요.** 격차가 큰 항목
(facet +0.077, MMR −0.106)은 16토픽에서도 안전했습니다.
